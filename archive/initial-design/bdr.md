## 1. 문서 목적

이 문서는 프로젝트를 추진하는 이유, 달성할 목표, 제품 범위와 성공 기준을 정의한다. 기능의 상세 동작은 FDD에서, 성능·보안·가용성 기준은 NFR에서, 기술 선택은 ADR에서 다룬다.

## 2. 서비스 및 프로젝트 요약

본 프로젝트는 웹 기반 중고거래 플랫폼을 구축한다. 사용자는 이메일과 비밀번호로 회원가입하거나 외부 신원 제공자를 통해 가입·로그인하고, 판매 게시글을 등록하며, 관심 상품을 관리하고 다른 사용자와 거래 및 메시지를 주고받을 수 있다. 거래 결과에 따라 현금 가치가 없는 내부 보상 포인트를 적립·조정한다. 운영자는 신고, 사용자 상태 및 게시글을 관리한다. 플랫폼 이용 안내를 위한 외부 LLM 기반 AI 챗봇도 제공한다.

중고거래는 프로젝트의 목적이 아니라 복합적인 서비스 요구를 제공하는 대상 도메인이다. 프로젝트의 주된 목적은 다음 역량을 설계·구현·검증하는 것이다.

- MAU 100만 명을 가정한 확장 가능한 서비스 인프라
- 인증·인가, 개인정보, Secret 및 감사 로그를 포함한 보안 설계
- 이미지, 검색, 채팅, 알림, 외부 API 등 서로 다른 부하 특성의 처리
- 장애 탐지, 복구, 배포 및 용량 관리가 가능한 운영 체계
- 소규모 팀이 운영할 수 있는 복잡도와 비용의 통제

## 3. 배경 및 문제 정의

단순 CRUD 예제는 대규모 서비스에서 발생하는 확장성, 비동기 처리, 실시간 연결, 데이터 일관성, 외부 서비스 장애 및 운영 보안 문제를 충분히 드러내지 못한다. 반대로 처음부터 다수의 마이크로서비스나 고가용성 구성을 무조건 도입하면 팀 규모에 비해 운영 복잡도가 과도해질 수 있다.

이 프로젝트는 실제 서비스와 유사한 도메인 흐름을 바탕으로 다음 질문에 검증 가능한 답을 만드는 데 초점을 둔다.

1. 트래픽이 증가해도 핵심 기능을 안정적으로 제공할 수 있는가?
2. 사용자·관리자·서비스 권한이 분리되고 중요 자산이 보호되는가?
3. 장애나 외부 연동 실패를 격리하고 정해진 시간 안에 복구할 수 있는가?
4. 로그, 메트릭, 추적 정보만으로 문제를 발견하고 원인을 분석할 수 있는가?

- 이메일·비밀번호 회원가입과 로그인, 외부 신원 제공자 로그인, 로그아웃 및 계정 상태 관리
- 이메일 인증, 비밀번호 변경·재설정 및 전체 세션 만료
- 사용자 프로필 조회·수정 및 회원 탈퇴
- 역할과 리소스 소유권에 따른 접근 제어
- 중고거래 게시글과 다중 이미지의 등록·조회·수정·삭제
- 카테고리·조건·키워드 기반 검색, 필터 및 정렬
- 관심 상품 등록·해제와 목록 조회
- 거래 요청, 수락·거절·취소·완료 및 거래 상태 이력
- 거래 상태에 연동된 내부 포인트 적립·취소·조정과 포인트 내역 조회
- 거래 참여자 간 메시지와 읽음 상태
- 게시판, 댓글 및 공지
- 게시글·사용자·댓글 신고와 관리자 처리
- 거래·채팅·신고·공지 관련 알림과 사용자별 수신 설정
- 거래 완료 후 후기와 별점
- 플랫폼 이용 안내용 AI 챗봇
- 관리자 전용 사용자·게시글·신고·운영 현황 관리

### 7.2 플랫폼 및 운영 범위

### 7.3 범위 외

- 실제 결제 및 정산
- GPS 기반 위치 추적과 근거리 추천
- 개인화 추천, 이미지 유사도 검색 등 고급 추천

## 8. 대표 사용자 시나리오

### UC-001 상품 등록과 거래 완료

1. 판매자가 외부 계정으로 로그인한다.
2. 상품 정보와 이미지를 등록한다.
3. 구매자가 상품을 검색하고 상세 정보를 확인한다.
4. 구매자가 거래를 요청하고 판매자와 메시지를 주고받는다.
5. 판매자가 요청을 수락하고 거래 상태를 변경한다.
6. 판매자와 구매자가 거래 완료를 상호 확인하면 포인트가 적립된다.
7. 거래 완료 후 양측은 결과를 확인하고 후기를 작성할 수 있다.

### UC-002 신고와 운영 조치

1. 사용자가 부적절한 게시글, 댓글 또는 사용자를 신고한다.
2. 관리자가 신고 근거와 대상 상태를 확인한다.
3. 관리자가 신고를 기각하거나 콘텐츠 숨김, 삭제, 사용자 제한 조치를 수행한다.
4. 시스템은 조치 사유와 관리 행위를 기록하고 신고자에게 결과를 알린다.

### UC-003 외부 서비스 장애

1. 사용자가 AI 챗봇 또는 외부 인증 기능을 이용한다.
2. 외부 제공자가 지연되거나 오류를 반환한다.
3. 시스템은 실패를 격리하고 사용자에게 안전한 오류를 제공한다.
4. 운영자는 지표와 추적 정보로 영향을 확인한다.
5. 핵심 거래 기능은 외부 AI 장애의 영향을 받지 않는다.

| BR-007 | 챗봇은 플랫폼 안내 범위에서 동작하며 거래 당사자의 판단이나 관리자 조치를 대신하지 않는다. |
| BR-008 | 실제 금전 결제와 정산은 플랫폼에서 처리하지 않는다. |
| BR-009 | 포인트는 현금으로 환전·출금·양도할 수 없는 내부 보상 단위이며 결제 수단으로 사용하지 않는다. |
| BR-010 | 포인트 원장은 기존 항목을 수정·삭제하지 않고 적립·취소·만료·관리 조정을 별도 항목으로 추가한다. |
| BR-011 | 동일 거래 이벤트로 동일 사용자에게 포인트를 중복 적립하거나 중복 취소할 수 없다. |
| BR-012 | 하나의 중고거래 게시글에는 최대 5개의 이미지를 연결할 수 있다. |

## 11. 가정

- MAU 100만 명은 출시 직후 실사용자 예측이 아니라 인프라 설계·검증 기준이다.
- 초기 운영은 단일 AWS 리전과 복수 가용 영역을 사용한다.
- 사용자는 이메일·비밀번호 또는 외부 신원 제공자를 통해 가입·로그인할 수 있다.
- 자체 비밀번호는 제품 데이터베이스에 저장하지 않고 승인된 인증 시스템에서 안전하게 검증·보호한다.
- AI 챗봇은 외부 LLM API를 사용하며 핵심 거래 기능과 장애 경계를 분리한다.
- 내부 포인트는 실제 금전 이동과 분리된 보상 기능으로 운영하며, 적립률·상한·소멸 정책은 출시 전에 확정한다.
