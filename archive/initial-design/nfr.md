# NFR — 비기능 요구사항

| 항목 | 값 |
|---|---|
| 문서 상태 | Draft |
| 기준 버전 | 0.2 |
| 선행 문서 | BDR 0.2 |
| 검증 원칙 | 각 요구사항은 지표, 시험 또는 증적으로 판정 가능해야 함 |

## 1. 목적과 적용 원칙

이 문서는 서비스가 어떤 품질 수준으로 동작해야 하는지를 정의한다. 기술 제품명이나 구현 선택은 ADR에서 다룬다.

아래 수치는 MAU 100만 명 규모를 검증하기 위한 **초기 설계 기준선**이다. 실제 사업 예측치가 아니며, 트래픽 모델과 비용 상한이 확정되면 버전을 올려 보정한다.

요구사항 우선순위는 다음과 같다.

- `MUST`: 출시 승인에 필수
- `SHOULD`: 정당한 예외와 후속 계획이 있어야 미충족 허용
- `MAY`: 비용과 일정에 따라 선택

## 3. 가용성 및 신뢰성

| ID | 우선순위 | 요구사항 | 검증/지표 |
|---|---|---|---|
| NFR-REL-001 | MUST | 핵심 API의 월간 가용성 목표는 99.9% 이상이어야 한다. | 합성 모니터링 기준 성공률 |
| NFR-REL-002 | MUST | 인증, 게시글 조회·등록, 거래 및 메시지 저장은 단일 인스턴스 장애로 중단되어서는 안 된다. | 인스턴스 종료 장애 시험 |
| NFR-REL-003 | MUST | 단일 가용 영역 장애 시 데이터 손실 없이 10분 이내 정상화해야 한다. | 가용 영역 장애 훈련 |
| NFR-REL-004 | MUST | 지역 재해 복구 목표는 RPO 15분 이내, RTO 4시간 이내로 한다. | 백업 복원 훈련 |
| NFR-REL-005 | MUST | 운영자 오조작에 대한 데이터 복구 목표는 RPO 5분 이내, RTO 60분 이내로 한다. | 시점 복구 시험 |
| NFR-REL-006 | MUST | 외부 LLM 장애는 인증, 게시글, 거래 및 채팅 저장 기능으로 전파되어서는 안 된다. | 장애 주입 시험 |
| NFR-REL-007 | MUST | 재시도 가능한 비동기 작업은 멱등성을 보장하고 최대 재시도 후 격리해야 한다. | 중복 이벤트/실패 주입 시험 |
| NFR-REL-008 | SHOULD | 계획된 배포 중 핵심 읽기 기능의 중단은 없어야 한다. | 배포 중 합성 테스트 |
| NFR-REL-009 | MUST | 알림 SSE 연결이 끊긴 사용자는 마지막 수신 이벤트 이후의 알림을 재조회해 누락을 복구할 수 있어야 한다. | 연결 종료·재연결 시험 |

가용성 계산에서 클라이언트 오류, 사전 공지된 유지보수 제외 여부는 운영 정책 확정 시 별도로 정의한다.

## 5. 보안

### 5.1 인증과 세션

| ID | 우선순위 | 요구사항 |
|---|---|---|
| NFR-SEC-001 | MUST | 사용자 로그인은 표준 OAuth 2.0/OIDC 흐름을 사용하고 웹 클라이언트는 Authorization Code와 PKCE를 사용해야 한다. |
| NFR-SEC-002 | MUST | 자체 비밀번호는 평문 또는 복호화 가능한 형태로 저장하지 않고, 검증된 관리형 인증 서비스 또는 고유 Salt가 적용된 적응형 단방향 해시로 보호해야 한다. |
| NFR-SEC-003 | MUST | Access Token 유효기간은 30분, Refresh Token 유효기간은 최대 14일로 하고 Refresh Token은 회전·폐기 가능해야 한다. |
| NFR-SEC-004 | MUST | 로그아웃, 회원 정지, 탈퇴 및 보안 이벤트 발생 시 후속 세션 사용을 차단할 수 있어야 한다. |
| NFR-SEC-005 | MUST | 관리자 계정은 다중 요소 인증을 적용해야 한다. |
| NFR-SEC-006 | MUST | 인증 실패와 토큰 재발급은 사용자·IP·디바이스 기준 속도 제한과 이상 징후 탐지를 적용해야 한다. |
| NFR-SEC-007 | MUST | 토큰, 세션 식별자 및 인증 코드는 URL, 분석 이벤트 또는 애플리케이션 로그에 기록하지 않아야 한다. |
| NFR-SEC-008 | MUST | 비밀번호는 최소 12자, 최대 128자를 허용하고 알려진 유출 비밀번호와 사용자 식별정보를 포함한 취약한 비밀번호를 거부해야 한다. |
| NFR-SEC-009 | MUST | 비밀번호 변경과 재설정 후 기존 Refresh Token과 활성 세션을 모두 폐기해야 한다. |
| NFR-SEC-010 | MUST | 이메일 인증 및 비밀번호 재설정 코드는 10분 이내 만료되고 한 번만 사용할 수 있으며 시도 횟수를 제한해야 한다. |
| NFR-SEC-011 | MUST | 계정 존재 여부는 로그인·가입·비밀번호 재설정 오류 응답으로 추론할 수 없도록 보호해야 한다. |
| NFR-SEC-012 | MUST | 브라우저는 Refresh Token을 Local Storage에 저장하지 않아야 하며 Secure·HttpOnly·SameSite 정책이 적용된 보호 저장 경계를 사용해야 한다. |

| NFR-AUTHZ-002 | MUST | 일반 사용자와 관리자 권한을 분리하고 기본 권한은 거부로 처리해야 한다. |

| NFR-DATA-008 | MUST | 삭제 요청이 승인되면 대상은 즉시 일반 조회에서 제외하고 논리 삭제 상태로 전환해야 한다. |
| NFR-DATA-009 | MUST | 보존기간이 끝나고 법적 보존·분쟁·보안 조사 예외가 없으면 자동화된 수명주기 작업으로 원본과 파생 데이터를 물리 삭제 또는 비가역 익명화해야 한다. |
| NFR-DATA-010 | MUST | 일반 제품 관리자는 임의의 즉시 Hard Delete 기능을 사용할 수 없어야 한다. 긴급 파기는 별도 승인된 운영 절차와 감사 기록을 요구한다. |

| ID | 우선순위 | 요구사항 |
|---|---|---|

| NFR-CON-002 | MUST | 동일 거래에 대한 경합 요청이 잘못된 이중 수락 또는 이중 완료를 만들지 않아야 한다. |
| NFR-CON-003 | MUST | 관심 수, 읽지 않은 알림 수 등 파생 카운터는 원본 관계를 진실의 원천으로 두고 재계산 가능해야 한다. |
| NFR-CON-004 | MUST | 이벤트 발행과 업무 데이터 변경 사이의 유실을 방지해야 한다. |
| NFR-CON-005 | SHOULD | 검색 색인과 알림은 최종 일관성을 허용하되 변경 후 10초 이내 반영해야 한다. |
| NFR-CON-006 | MUST | 시간은 UTC로 저장하고 사용자 표시에만 지역 시간대를 적용해야 한다. |

## 7. 포인트 원장과 잔액 무결성

| ID | 우선순위 | 요구사항 |
|---|---|---|
| NFR-POINT-001 | MUST | 포인트 원장은 append-only 방식으로 기록하고 기존 항목을 수정·삭제하지 않아야 한다. |
| NFR-POINT-002 | MUST | 포인트 적립·취소·조정 요청은 거래 이벤트 ID, 사용자 ID 및 처리 유형 조합으로 멱등성을 보장해야 한다. |
| NFR-POINT-003 | MUST | 거래 완료 상태 변경과 포인트 원장 기록은 하나의 원자적 업무 처리로 확정하거나, 실패 시 자동 보상 가능한 구조를 사용해야 한다. |
| NFR-POINT-004 | MUST | 표시 잔액은 원장으로부터 재계산할 수 있어야 하며 원장 합계와 불일치하면 경보를 발생시켜야 한다. |
| NFR-POINT-005 | MUST | 거래 취소 시 미확정 포인트는 취소하고, 이미 반영된 포인트의 정정은 기존 항목 삭제가 아닌 보상 원장 항목으로 처리해야 한다. |
| NFR-POINT-006 | MUST | 관리자 포인트 조정은 사유, 대상, 조정량, 수행자 및 승인 정보를 감사 로그에 기록해야 한다. |
| NFR-POINT-007 | MUST | 포인트는 현금 환전·사용자 간 양도·출금 및 실제 결제에 사용할 수 없어야 한다. |
| NFR-POINT-008 | SHOULD | 포인트 원장과 잔액의 전수 대사를 하루 1회 이상 수행해야 한다. |

| NFR-OBS-002 | MUST | 구조화 로그, 핵심 메트릭 및 분산 추적을 통해 오류 원인을 단일 사용자 흐름 단위로 추적할 수 있어야 한다. |

| NFR-OBS-008 | MUST | 주요 경보에는 담당자, 심각도, 대응 절차 링크와 에스컬레이션 기준이 있어야 한다. |
