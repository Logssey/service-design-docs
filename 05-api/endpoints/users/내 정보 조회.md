# 내 정보 조회

도메인: USERS
Method: GET
URL: /api/v1/users/me
Version: 1
개발완료여부: Yes

**인증** `USER`

**Response** `MyProfileResponse`

```java
// MyProfileResponse (200)
{
  "userId": 1,
  "nickname": "재현",
  "profileImageUrl": "https://...",
  "bio": "안녕하세요",
  "role": "USER",
  "status": "ACTIVE",
  "suspendedUntil": null,
  "provider": "LOCAL",
  "email": "user@example.com",
  "emailVerified": false,
  "createdAt": "2026-01-10T03:00:00Z"
}
```

`provider`는 이 계정의 인증 수단(`KAKAO` / `LOCAL`)이다. 화면에서 비밀번호 변경 메뉴 노출 여부를 판단하는 데 쓴다.

`email`은 인증 수단에 등록된 이메일 주소다. `LOCAL`은 가입 이메일이고, 소셜 계정은 온보딩에서 입력했을 때만 값이 있으며 입력하지 않았으면 `null`이다 (ADR-016). 사용자가 등록한 주소를 확인하고 오타를 알아차릴 수 있도록 싣는다.

`emailVerified`는 등록된 이메일의 소유 확인 여부이며, 이메일이 없으면 `false`다. 화면은 `email`이 있고 `emailVerified`가 `false`일 때만 미인증 상태와 재발송을 표시한다 (`FR-AUTH-014`).

> 세 필드(`provider`, `email`, `emailVerified`)는 본인 응답인 `MyProfileResponse`에만 둔다. 공용 `UserSummaryResponse`나
> 판매자 프로필, 관리자 회원 목록 응답에 넣으면 다른 사용자의 인증 수단·이메일 주소·인증 상태까지 노출된다.
> 가입 직후 `AuthTokenResponse`에도 실을지는 프론트 화면 흐름 확인 후 결정한다.

관련: `FR-AUTH-005`, `FR-AUTH-014`, `FR-AUTH-017`
