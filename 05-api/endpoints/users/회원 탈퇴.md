# 회원 탈퇴

도메인: USERS
Method: DELETE
URL: /api/v1/users/me
Version: 1
개발완료여부: Yes

회원 탈퇴. [규칙 명세 3절](<../../../02-functional-design/business-rules.md#3-탈퇴-처리>) 절차를 단일 트랜잭션으로 수행한다 (ADR-012).

**인증** `USER` — `ADMIN` 계정은 탈퇴할 수 없다. 이용정지 중인 회원은 탈퇴할 수 있다.

**Request** 본문 없음

**Response** 없음 (204)

```http
HTTP/1.1 204 No Content
Set-Cookie: refresh_token=; Max-Age=0; Path=/api/v1/auth; HttpOnly; Secure; SameSite=Lax
```

**서버 처리** (한 트랜잭션, 순서대로)

1. 회원 행을 잠그고 상태를 확인한다. 이미 탈퇴했으면 401, `USER`가 아니면 403이다.
2. 탈퇴 회원이 판매자이거나 구매자인 `REQUESTED`/`ACCEPTED` 거래를 모두 `CANCELED`로 바꾼다. 거래 상태 이력에 사유 `회원 탈퇴`를 남긴다.
3. 취소한 거래가 `ACCEPTED`였고 탈퇴 회원이 구매자였다면 판매자의 `RESERVED` 게시글을 `ON_SALE`로 되돌린다.
4. 거래 상대방에게 `TRADE_CANCELED` 알림을 보낸다 ("상대방의 회원 탈퇴로 진행 중인 거래가 취소되었습니다.").
5. 프로필 이미지 연결을 끊고 `user_identities` 행을 삭제한다 (ADR-018).
6. `nickname`을 `탈퇴회원#{user_id}`로 바꾸고 `bio`·`profile_image_url`·`suspended_until`을 비운다. `status = 'WITHDRAWN'`이 되고 `withdrawn_at`이 기록된다.
7. 이 회원의 Refresh Token을 모두 폐기한다.

- 게시글, 커뮤니티 글·댓글, 후기, 채팅 메시지는 지우지 않는다.
- 인증 식별자를 지우므로 같은 카카오 계정이나 이메일로 다시 가입할 수 있다. 이때는 이전 이력과 연결되지 않은 새 계정이다.
- Access Token은 만료(최대 30분)까지 서명상 유효하다. 그러나 탈퇴 회원의 토큰은 회원 상태를 다시 확인하는 API에서 401로 거절된다. 클라이언트는 응답을 받는 즉시 세션을 정리한다.
- 요청 쿠키 경로(`/api/v1/auth`)와 이 URL이 달라 요청에는 쿠키가 실리지 않는다. 그래도 응답의 `Set-Cookie`가 같은 경로로 쿠키를 만료시킨다.

| 오류 | 상황 |
| --- | --- |
| 401 `UNAUTHENTICATED` | Access Token이 없거나 만료·위조됨, 회원이 없거나 이미 탈퇴함 |
| 403 `FORBIDDEN` | 토큰 또는 DB의 역할이 `USER`가 아님 (관리자 계정) |

**클라이언트 처리** ([MY-003](<../../../02-functional-design/screen-design/my-account.md#my-003-회원-탈퇴>))

| 결과 | 처리 |
| --- | --- |
| 204 | 세션 정리 후 AUTH-001로 이동 ("회원 탈퇴가 완료되었습니다.") |
| 401 (재발급도 실패) | 세션 정리 후 AUTH-001로 이동 ("다시 로그인해 주세요.") |
| 403 | "관리자 계정은 탈퇴할 수 없습니다." 탈퇴하기 버튼 비활성 유지 |
| 5xx · 네트워크 오류 | "탈퇴하지 못했습니다. 잠시 후 다시 시도해 주세요." 다시 누를 수 있다 |

탈퇴 화면에서 취소될 거래를 미리 보여 줄 때는 [거래 목록 조회](<../trades/거래 목록 조회.md>)를 `role` 없이 `status=REQUESTED`, `status=ACCEPTED`로 두 번 부른다.

관련: `FR-AUTH-009~011`, `NFR-AUTH-003`
