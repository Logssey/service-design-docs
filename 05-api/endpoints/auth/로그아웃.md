# 로그아웃

도메인: AUTH
Method: POST
URL: /api/v1/auth/logout
Version: 1
개발완료여부: Yes

이 기기의 로그인을 끝낸다. 요청에 실린 Refresh Token을 화이트리스트에서 제거하고 쿠키를 만료시킨다. 다른 기기의 Refresh Token은 그대로 둔다.

**인증** `USER` — Access Token이 필요하다. 역할은 따지지 않으므로 `ADMIN`도 호출할 수 있다.

**Request** 본문 없음. `refresh_token` 쿠키(`Path=/api/v1/auth`)는 브라우저가 자동으로 싣는다.

**Response** 없음 (204)

```http
HTTP/1.1 204 No Content
Set-Cookie: refresh_token=; Max-Age=0; Path=/api/v1/auth; HttpOnly; Secure; SameSite=Lax
```

- 쿠키가 없거나 이미 폐기된 토큰이어도 204다. 폐기할 것이 없을 뿐 로그아웃은 성공한다.
- Access Token은 서버가 폐기할 수 없어 만료(최대 30분)까지 유효하다 (ADR-005). 클라이언트는 응답을 받는 즉시 메모리의 Access Token을 버린다. 채팅 서버도 서명만 검증하므로 열린 소켓은 클라이언트가 끊는다.
- 감사 로그 `AUTH_LOGOUT`을 남긴다. 별도 트랜잭션으로 기록하고, 기록이 실패해도 로그아웃은 성공한다.

| 오류 | 상황 |
| --- | --- |
| 401 `UNAUTHENTICATED` | Access Token이 없거나 만료·위조됨 |

**클라이언트 처리** ([MY-001-D1](<../../../02-functional-design/screen-design/my-account.md#my-001-d1-로그아웃-확인>))

| 결과 | 처리 |
| --- | --- |
| 204 | 세션 정리 후 AUTH-001로 이동 |
| 401 (재발급도 실패) | 이미 세션이 끝났으므로 204와 같게 처리 |
| 5xx · 네트워크 오류 | 로그인 상태를 유지하고 다시 시도하게 한다. 쿠키가 남아 있어 로컬 상태만 지우면 새로고침할 때 다시 로그인된다. |

관련: `FR-AUTH-004`, `NFR-AUTH-003`
