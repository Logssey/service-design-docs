# 소셜 온보딩

도메인: AUTH
Method: POST
URL: /api/v1/auth/signup
Version: 1
개발완료여부: Yes

소셜 로그인으로 진입한 신규 회원의 온보딩 완료. 이메일 계정 가입은 [이메일 가입](<이메일 가입.md>)을 사용한다.

**인증** — (signupToken)

**Request** `SignupRequest`

**Response** `AuthTokenResponse`

```java
// SignupRequest
{
  "signupToken": "eyJhbGci...",   // @NotBlank
  "nickname": "재현",                  // @NotBlank @Size(min=2, max=20)
  "email": "user@example.com",        // 선택. @Email @Size(max=254). 생략·null·""이면 이메일 없이 가입
  "emailCollectionAgreed": true,      // 선택  이메일 수집·이용 동의. email을 보내면 true여야 함
  "termsOfServiceAgreed": true,       // @AssertTrue  이용약관
  "privacyPolicyAgreed": true         // @AssertTrue  개인정보 처리방침
}

// AuthTokenResponse (201)
{
  "accessToken": "eyJhbGci...",
  "user": {
    "userId": 1,
    "nickname": "재현",
    "profileImageUrl": null
  }
}
```

가입이 확정되면 `users` 행과 함께 해당 제공자의 `user_identities` 행을 생성한다 (ADR-017).

필수 약관 2건은 **각각 동의를 받는다.** 개인정보보호법 제22조가 동의 사항을 구분해 받도록 요구하므로 하나의 필드로 합치지 않는다. 동의 시각은 `users.terms_agreed_at`에 기록한다.

`email`은 선택 항목이다. 생략·`null`·빈 문자열이면 입력하지 않은 것으로 보며, 공백만 있는 값, 앞뒤 공백이 붙은 값, 형식 위반, 254자 초과는 `400`이다. 서버는 앞뒤 공백을 잘라 받아 주지 않으므로 클라이언트가 잘라서 보낸다. 저장 전에 소문자로 정규화한다. 입력하면 해당 제공자의 `user_identities.email`에 저장하고 가입 직후 소유 확인 코드를 1회 발송한다. 발송·확인 절차와 제한은 이메일 계정과 같다 ([이메일 소유 확인 코드 발송](<이메일 소유 확인 코드 발송.md>), [이메일 소유 확인](<이메일 소유 확인.md>)). 소유 확인 전에도 서비스 이용을 제한하지 않으며, 메일 발송 실패는 가입을 되돌리지 않는다 (ADR-019).

`emailCollectionAgreed`는 이메일 수집·이용에 대한 **선택 동의**다. 필수 약관과 같은 이유로 별도 필드로 받는다. `email`을 입력했는데 `true`가 아니면(생략·`null`·`false`) `400`이다. 동의하면 동의 시각을 `user_identities.email_consent_at`에 기록한다. `email`을 입력하지 않았으면 이 값은 무시하고 저장하지 않는다.

소셜 계정의 이메일은 식별자가 아니다. 온보딩에서는 중복을 검사하지 않으므로, 같은 주소의 `LOCAL` 계정이나 다른 소셜 계정이 있어도 가입에 성공하며 계정은 병합되지 않는다. 소유 확인이 끝난 소셜 이메일은 한 계정에만 둘 수 있으며, 이 판정은 [이메일 소유 확인](<이메일 소유 확인.md>) 단계에서 한다. 입력 단계에서 막으면 확인 전 주소로 타인의 이메일을 선점할 수 있고, 소유 증명 없이 그 이메일의 가입 여부가 드러난다 (`NFR-AUTH-018`). 소셜 계정의 이메일은 이메일 로그인과 비밀번호 재설정에도 쓰이지 않는다 (ADR-004, ADR-016, ADR-019).

| 오류 | 상황 |
| --- | --- |
| 400 `INVALID_INPUT` | 닉네임 형식 위반, 이메일 형식·길이 위반, 이메일 입력 후 수집·이용 미동의, 약관 미동의 |
| 401 `UNAUTHENTICATED` | signupToken 만료 |
| 409 `CONFLICT` | 닉네임 중복, 이미 가입된 소셜 계정(같은 signupToken으로 재요청) |

관련: `FR-AUTH-002`, `FR-AUTH-014`, `FR-AUTH-017`
