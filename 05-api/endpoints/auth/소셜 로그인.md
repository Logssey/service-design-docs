# 소셜 로그인

도메인: AUTH
Method: POST
URL: /api/v1/auth/oauth/{provider}
Version: 1
개발완료여부: Yes

소셜 제공자의 인가 코드로 로그인 또는 가입 진입.

**인증** —

**Path Variable**

| 이름 | 값 | 설명 |
| --- | --- | --- |
| `provider` | `kakao` | 소문자로 받는다. 1차 릴리스는 `kakao`만 허용 (ADR-004) |

**Request** `OAuthLoginRequest`

**Response** `OAuthLoginResponse`

```java
// OAuthLoginRequest
{
  "code": "인가코드",                                  // @NotBlank
  "redirectUri": "https://reused.app/oauth/callback"  // @NotBlank
}

// OAuthLoginResponse — 기존 회원 (200)
{
  "status": "LOGIN",
  "accessToken": "eyJhbGci...",
  "signupToken": null,
  "user": {
    "userId": 1,
    "nickname": "재현",
    "profileImageUrl": "https://..."
  }
}

// OAuthLoginResponse — 신규 회원 (200)
{
  "status": "SIGNUP_REQUIRED",
  "accessToken": null,
  "signupToken": "eyJhbGci...",
  "user": null
}
```

`status`는 `LOGIN` / `SIGNUP_REQUIRED`. `user`는 `UserSummaryResponse`.

Refresh Token은 바디가 아닌 HttpOnly 쿠키로 설정한다.

`signupToken`은 제공자 회원번호를 담은 단기 토큰(10분)이다. 인가 코드는 일회용이므로 온보딩 중 만료를 방지하기 위해 별도 토큰으로 전달한다. `typ` 헤더는 `signup+jwt`이며 온보딩 엔드포인트가 이를 검증한다 (공통 규약 0.3).

제공자 연동은 교체 가능한 단일 인터페이스로 구현한다. 제공자를 추가할 때 이 엔드포인트의 계약은 바뀌지 않으며 `provider` 허용값과 구현체만 늘어난다 (ADR-016).

소셜 계정에는 이메일과 비밀번호를 저장하지 않는다. 카카오 이메일은 확보를 보장할 수 없으므로 요청하지 않는다 (ADR-016).

| 오류 | 상황 |
| --- | --- |
| 400 `INVALID_INPUT` | 인가 코드 누락·무효 |
| 403 `USER_SUSPENDED` | 이용정지 계정 |
| 404 `NOT_FOUND` | 지원하지 않는 `provider` |
| 502 `EXTERNAL_SERVICE_ERROR` | 제공자 API 실패 |

관련: `FR-AUTH-001`, `FR-AUTH-003`
