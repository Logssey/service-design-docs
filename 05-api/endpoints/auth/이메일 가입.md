# 이메일 가입

도메인: AUTH
Method: POST
URL: /api/v1/auth/email/signup
Version: 1
개발완료여부: No

이메일·비밀번호로 회원가입. 소셜 온보딩과 달리 단일 요청으로 가입이 확정된다.

**인증** —

**Request** `EmailSignupRequest`

**Response** `AuthTokenResponse`

```java
// EmailSignupRequest
{
  "email": "user@example.com",   // @NotBlank @Email @Size(max=254)
  "password": "hunter22!",        // @NotBlank @Size(min=8, max=128)
  "nickname": "재현",                  // @NotBlank @Size(min=2, max=20)
  "termsOfServiceAgreed": true,       // @AssertTrue  이용약관
  "privacyPolicyAgreed": true         // @AssertTrue  개인정보 처리방침
}

// AuthTokenResponse (201)
{
  "accessToken": "eyJhbGci...",
  "user": {
    "userId": 11,
    "nickname": "재현",
    "profileImageUrl": null
  }
}
```

가입 직후 로그인 상태로 전환하고 소유 확인 메일을 발송한다. **소유 확인 전에도 서비스 이용을 제한하지 않는다.**

`provider='LOCAL'`인 `user_identities` 행을 생성하며, 식별자는 서버가 발급한 UUID다. 이메일은 `LOCAL` 범위에서만 유일하므로 같은 주소로 소셜 계정이 존재해도 별개 계정이며 병합하지 않는다 (ADR-016, ADR-017).

비밀번호는 고유 Salt가 적용된 적응형 단방향 해시로 저장한다 (`NFR-AUTH-014`).

필수 약관 2건은 소셜 온보딩과 동일하게 **각각 동의를 받는다.**

| 오류 | 상황 |
| --- | --- |
| 400 `INVALID_INPUT` | 이메일 형식 위반, 비밀번호 길이 위반, 약관 미동의 |
| 409 `CONFLICT` | 이메일 중복 또는 닉네임 중복 |

관련: `FR-AUTH-012`, `NFR-AUTH-014`, `NFR-AUTH-015`
