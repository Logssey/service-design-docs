# 이메일 소유 확인

도메인: AUTH
Method: POST
URL: /api/v1/auth/email/verification/confirm
Version: 1
개발완료여부: Yes

발송된 코드로 인증 수단에 등록된 이메일의 소유를 확인한다. `LOCAL` 계정과 이메일을 등록한 소셜 계정이 같은 절차를 쓴다 (ADR-019).

**인증** `USER`

**Request** `EmailVerificationConfirmRequest`

**Response** 없음 (204)

```java
// EmailVerificationConfirmRequest
{
  "code": "483920"   // @NotBlank
}
```

성공하면 `user_identities.email_verified_at`을 기록하고 코드를 폐기한다.

**만료·재사용·불일치를 구분하지 않고 같은 코드로 응답한다.** 코드당 검증 시도는 5회로 제한하며, 초과하면 해당 코드를 폐기한다 (`NFR-AUTH-017`). 이메일이 없는 소셜 계정이나 이미 확인된 계정에는 발급된 코드가 없으므로 같은 `400 INVALID_INPUT`으로 끝난다.

**소유 확인이 끝난 소셜 이메일은 한 계정에만 둔다.** 소셜 계정의 코드가 맞더라도 같은 주소가 다른 소셜 인증 수단에서 이미 확인되어 있으면 `409 CONFLICT`로 거절한다. 이때 코드를 폐기하지 않고 `email_verified_at`도 기록하지 않는다. 코드가 맞을 때만 이 판정을 하므로, 그 주소에 확인된 계정이 있다는 사실은 코드로 소유를 증명한 사용자에게만 드러난다 (`NFR-AUTH-018`). 동시에 확인하면 부분 UNIQUE 인덱스 `uq_user_identities_email_social_verified`가 한 건만 통과시키고 나머지는 같은 `409`로 응답한다.

확인 전 주소와 `LOCAL` 계정의 이메일은 이 판정의 대상이 아니다. 같은 주소의 `LOCAL` 계정이 있어도 소셜 계정의 확인은 성공하며, 두 계정은 별개로 남는다 (ADR-016, ADR-019).

| 오류 | 상황 |
| --- | --- |
| 400 `INVALID_INPUT` | 코드 만료·재사용·불일치 |
| 409 `CONFLICT` | 같은 이메일이 다른 소셜 계정에서 이미 소유 확인됨 |
| 429 `RATE_LIMITED` | 검증 시도 제한 초과 |

관련: `FR-AUTH-014`, `FR-AUTH-017`, `NFR-AUTH-017`, `NFR-AUTH-018`
