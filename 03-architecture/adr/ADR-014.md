# ADR-014 — 인앱 알림 전용, 폴링 기반 조회

**상태** Accepted

**맥락**

`FR-NOTI-001`은 알림 발송을 요구하나 외부 채널은 범위에서 제외되었다. 알림만을 위한 별도 실시간 전달 채널은 구현 부담이 크다.

**결정**

- 알림은 인앱 전용으로 제공한다
- 알림은 데이터베이스에 저장하고 클라이언트가 주기적으로 조회한다
- 별도의 실시간 전달 채널을 구성하지 않는다
- 알림 발송 실패가 원인이 된 업무 처리를 되돌리지 않는다

**근거**

- 알림 전용 실시간 채널은 1차 릴리스 범위 대비 구현 비용이 크다
- 폴링으로도 `FR-NOTI-001`~`004`를 충족할 수 있다

**대안**

- SSE 또는 WebSocket 전용 채널: 즉시성은 높으나 연결 관리 부담이 추가된다
- 채팅 WebSocket 공유: 연결은 절약되나 채팅 장애가 알림에 전파된다

**결과**

- 알림 확인에 폴링 주기만큼 지연이 발생한다
- 폴링 주기가 짧으면 불필요한 요청이 증가한다

**관련 요구사항** FR-NOTI-001~004, NFR-EXT-001
