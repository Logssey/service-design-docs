# ADR-005 — JWT 기반 인증과 Refresh Token 화이트리스트

**상태** Accepted — 비밀번호 변경·재설정 시 토큰 폐기는 ADR-016 참조

**맥락**

API 서버와 채팅 서버가 분리되어 인증 상태를 공유해야 한다. `NFR-AUTH-003`은 로그아웃·탈퇴 후 기존 인증 수단의 무효화를 요구하는데, 표준 JWT는 만료 전까지 폐기가 불가능하다.

**결정**

| **구분** | **Access Token** | **Refresh Token** |
| --- | --- | --- |
| 형태 | JWT | JWT 또는 무작위 문자열 |
| 유효기간 | 30분 | 14일 |
| 검증 | 서명 검증만 | Redis 화이트리스트 조회 |
| 클라이언트 보관 | 메모리 | HttpOnly·Secure 쿠키 |
- 발급된 Refresh Token은 Redis 화이트리스트에 등록하고, 등록되지 않은 토큰은 거부한다
- 재발급 시 기존 Refresh Token을 폐기하고 새로 발급한다(Rotation)
- 이미 사용된 Refresh Token이 재사용되면 해당 사용자의 전체 토큰을 무효화한다
- 로그아웃 시 화이트리스트에서 제거한다
- 서명 알고리즘은 대칭키(HS256)를 사용하며, `alg` 값을 서버에서 고정 검증한다

**근거**

- 화이트리스트는 블랙리스트와 달리 저장소 조회 실패 시 거부 측으로 동작하여 안전하다
- Rotation과 재사용 탐지로 토큰 탈취에 대응할 수 있다
- 채팅 서버는 서명 검증만으로 인증이 가능하여 중앙 세션 의존이 없다

**대안**

- 서버 세션: 즉시 폐기는 단순하나 채팅 서버가 세션 저장소를 공유해야 한다
- JWT 블랙리스트: 명시적으로 등록된 토큰만 차단되어 누락 시 통과한다

**결과**

- Redis 장애 시 토큰 재발급이 불가능하다
- Access Token은 30분간 폐기할 수 없으므로 이용정지 반영에 지연이 발생한다

**관련 요구사항** FR-AUTH-003, 004, NFR-AUTH-002~004, NFR-AUTH-012
