# ADR-018 — 탈퇴 시 인증 수단을 파기하고 재가입을 제한하지 않는다

**상태** Accepted

**맥락**

ADR-012는 탈퇴 시 소셜 계정 식별자를 단방향 해시로 변환해 보관하기로 했다. 근거는 이용정지 상태에서 탈퇴 후 재가입으로 제재를 우회하는 것을 탐지하기 위함이었다. ADR-017이 인증 수단을 `user_identities`로 분리하면서 같은 규칙이 `LOCAL` 계정의 이메일에도 적용됐다.

이 방식은 두 가지를 남긴다.

- 목적은 제재 회피 방지인데 실제로는 **모든 탈퇴자의 재가입을 영구 차단한다.** 제재받은 적 없는 사용자도 돌아올 수 없다
- 단순 해시는 이메일에 대해 익명성을 보장하지 못한다. 이메일 주소는 값 공간이 좁고 유출 목록이 널리 존재해 사전 공격으로 역산되며, 법적으로도 가명처리에 해당해 여전히 개인정보다. 서버 비밀키를 사용한 HMAC이라야 하지만 그러면 키 관리와 교체 문제가 따라온다

재가입 제한은 기능·비기능 요구사항 어디에도 없다. `NFR-AUTH-012`는 이용정지·탈퇴 **상태인 계정**의 이용 제한을 요구할 뿐이다. 재가입 차단은 ADR-012의 근거 절에서 파생된 판단이다.

**결정**

- 탈퇴 시 해당 회원의 `user_identities` 행을 삭제한다. `users` 행은 논리 삭제로 유지한다 (ADR-012 계승)
- 탈퇴한 인증 식별자와 이메일을 어떤 형태로도 보존하지 않는다
- 탈퇴 후 같은 식별자·이메일로 재가입하는 것을 제한하지 않는다
- 제재 회피 방지는 1차 릴리스 범위에 포함하지 않는다. 도입한다면 탈퇴와 독립적으로 제재 시점에 기록하는 별도 목록으로 다룬다

**근거**

- 인증 수단은 사람이 아니라 접근 경로이므로 탈퇴 시 제거하는 것이 의미상 자연스럽다. `users` 행이 남아 거래 이력·후기·평점은 그대로 보존된다
- 보존 대상이 사라지면 개인정보 보유량이 줄고, 해시의 익명성 전제를 검증할 필요도 없어진다
- C2C에서는 거래 완료 건수와 평점이 진입장벽으로 작동한다. 재가입 계정은 신뢰 정보가 0에서 시작하므로 자연적인 억제가 존재한다
- 제재 회피 방지가 필요해지면 제재 시점에 기록하는 목록이 정확하다. 탈퇴자 전체를 보존하는 방식은 목적에 비해 대상이 넓다

**대안**

- ADR-012 유지(탈퇴자 전체의 식별자 보존): 목적 대비 범위가 넓고, 이메일 해시의 익명성을 보장하지 못한다
- 제재 기록 목록 도입: 목적에 정확하나 비밀키 관리가 따라오며 요구사항에 없는 기능이다
- 재가입 유예기간: 보존 기간이 짧아질 뿐 보존 자체는 남고, 기간을 기다리는 회피는 막지 못한다

**결과**

- 이용정지 상태에서 탈퇴 후 재가입해 제재를 회피할 수 있다. 신뢰 정보가 초기화된다는 점이 유일한 억제 수단이다
- 탈퇴 회원은 인증 수단이 없어 구조적으로 로그인이 불가능하다 (`NFR-AUTH-012`)
- 같은 이메일로 재가입하면 별개의 새 계정이며 이전 이력과 연결되지 않는다
- ADR-012가 후속 과제로 남긴 "보존기간과 최종 파기 정책"은 보존 대상이 없어져 해소된다

**관련 요구사항** FR-AUTH-009~011, NFR-AUTH-012, NFR-DATA-010
