# ADR-015 — 프론트엔드 프레임워크 선택

**상태** Proposed — 프론트엔드 담당자 확정 후 결정

**맥락**

`4.1`은 모바일 웹 우선 반응형 웹을 요구한다. SSR은 범위에 포함되지 않으며 클라이언트 렌더링으로 구현한다. 두 후보 모두 React 기반이며 SPA로 동작한다.

**확정 사항**

- React 기반 SPA로 구현한다
- 서버 사이드 렌더링을 사용하지 않는다
- 빌드 결과물은 정적 파일로 배포한다
- 서버 상태 관리는 TanStack Query를 사용한다
- 클라이언트 상태 관리는 Zustand를 사용한다

**미확정 — 두 후보 중 택일**

| **항목** | **후보 A: React + Vite** | **후보 B: Next.js (CSR)** |
| --- | --- | --- |
| 라우팅 | react-router 직접 구성 | 파일 기반 라우팅 제공 |
| 빌드 설정 | Vite 설정 직접 관리 | 기본 제공 |
| 이미지 최적화 | 직접 구현 | next/image 제공 |
| 개발 서버 속도 | 빠름 | 상대적으로 느림 |
| 추가 학습 요소 | 없음 | App Router, 서버·클라이언트 컴포넌트 구분 |
| 배포 산출물 | 정적 파일 | static export 시 정적 파일 |

**선택 기준**

- 담당자가 Next.js 경험이 있으면 후보 B
- React 경험만 있거나 프레임워크 학습이 필요하면 후보 A
- 3주 일정에서 새로운 개념 학습이 부담되면 후보 A

**결정 기한** 개발 착수 전

**관련 요구사항** 4.1 서비스 제공 형태
